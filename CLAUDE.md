This is a custom desktop frontend for agent CLIs. Codex is the first harness;
Claude Code and maki (through the generic ACP driver) are specified in
`features/13-harnesses.md` and `docs/adr/0002-harness-interface.md`.
Vocabulary is in `GLOSSARY.md`.

A mirror codex source code can be found at `../codex-mirror`

## Frontend Best Practices

We use "Skeleton" as our component / styling library. Before creating a new component ALWAYS check if it already exists in Skeleton.
Skeleton's docs are vendored at `llms/skeleton.txt` Always use a subagent or attempt to find only the part you need to avoid bloating context.

### Design prototyping

The "Pingex" design system artifact (https://claude.ai/artifact/5yibz7n9w5i84J1PJXQjp2)
holds the app's tokens (Cerberus + Readable, light/dark), fonts and static
renditions of the `src/app.css` recipes. Prototype screens as a Design
artifact built on it, using the same class names the Svelte code uses
(`btn btn-sm preset-filled-primary-500`, `panel-card`, `pill`, `field`), so
markup ports back unchanged. Read its `project/README.md` before designing.
When `src/app.css` or `src/themes/*.css` change, update the system's
`tokens.json` and `components/bundle.css` to match.

## Supported Codex versions

We support three tiers of Codex at once — unstable (mirror `main`), stable
(latest release) and last stable — recorded with tags and commits in
`docs/SUPPORTED_VERSIONS.md` (policy: `docs/adr/0001-three-tier-codex-version-support.md`;
vocabulary: `GLOSSARY.md`). The app never branches on the version: an API some
tiers lack is a `Feature` in `src-tauri/src/codex/compat.rs`, probed once and
its refusal cached. When adopting a newer upstream API, add a `Feature` (with
`since`), a `*_UNSUPPORTED` constant in `src/lib/services/api.ts`, a row in
the matrix, and a live test that takes the legacy branch via `expect_legacy`.
`bun run versions:check` fails when the doc drifts from the mirror.

## Rust ↔ TypeScript bindings

`src/lib/bindings.ts` is generated by tauri-specta from the `#[tauri::command]`
functions and `specta::Type` structs in `src-tauri`. Regenerate it with
`bun run typegen` (it's rewritten on debug launch) and commit the
result. Frontend code imports the types via `$lib/types` and calls commands via
`commands.*` from `$lib/bindings`, never `invoke("...")`. Anything
that crosses the IPC boundary as raw JSON uses `crate::util::json::Json`.

## Harness drivers

Each non-Codex harness is a `Driver` (`src-tauri/src/harness/driver.rs`);
commands reach a thread's driver through `ctx.harness_thread(id)`, and Codex
stays on `ctx.session`. Drivers translate their wire protocol into
`HarnessEvent`s and never leak protocol vocabulary past their module: the
frontend reducer, the journal and the item types are harness-neutral.
Anything one harness can do that another cannot is a `Capability`, declared
by the driver or probed once; the frontend reads `can()`, `HARNESS_INFO` and
`HARNESS_MODES` and never checks the harness kind. A harness that speaks ACP
is a `HarnessKind` variant plus an `AcpSpec` (`src-tauri/src/acp/maki.rs` is
the model), with no new protocol code. When adding a harness, add a golden
fixture case under `tests/fixtures/protocol/<harness>/` and a live suite under
`src-tauri/tests/live_<harness>/`.

## Hosts

A Home lives on a `Host` (`src-tauri/src/util/host.rs`): native, or a WSL
distribution when the app runs on Windows. Spawn processes through
`host.command`, open files through `host.to_local`, and build paths with
`host.join_str`; never `Path::join` a Linux path or `Command::new` a harness
directly. Vocabulary in `GLOSSARY.md`, mechanics in `features/13-harnesses.md`
("Hosts"), rationale in `docs/adr/0003-host-per-home.md`.

## Git and GitHub

Run git through `run_git*` in `src-tauri/src/git/run.rs`, which applies the
fixed environment (`LC_ALL=C`, no optional locks, no prompts) that the error
classifiers rely on. Run GitHub through `run_gh` / `gh_graphql` in
`src-tauri/src/review/github/run.rs`, with a `Gh` that names the window's `Host`
and the repository's account; only `GhCli` builds one. Read pull-request
content by SHA from `refs/pingex/pr/*` (`git/objects.rs`); a branch name is
only for display. Tests build repositories with `git::test_repo::TestRepo`
and parse recorded GitHub JSON from `tests/fixtures/github/`. Rationale and
the write-side design: `docs/adr/0004-git-and-github-io.md`.

Frontend git and GitHub reads that pages repeat go through
`src/lib/services/queryCache.svelte.ts` (`query` in components,
`fetchQuery`/`readFresh` elsewhere). A new cached read needs a row in
`READS`. Every git and review command declares what it changes in `EFFECTS`
(`src/lib/services/commandEffects.ts`), and `bun run check` fails until a new
one does; cache invalidation, inbox resync and the branch chips derive from
it. Backend caches use
`util::ttl_cache::TtlCache` and always expire. They hold only SHA-keyed or
run-stable answers, never mutable git state.

## Working efficiently

Cost in this repo is context size times turn count, and the 1M-context model
never compacts, so what enters the conversation stays there.

- Delegate broad "where is X handled" searches to an Explore subagent and keep
  only its conclusion.
- Verify with the cheapest rung that proves the change (ladder in the `verify`
  skill): `bun run check` / `cargo check`, then `test:changed` /
  `rust:test:lib`, then `preflight` once before finishing. Not after every edit.
- In a `.claude/worktrees/*` checkout, set `CARGO_TARGET_DIR` to the main
  repo's `src-tauri/target` so cargo reuses the warm cache.
- `python3 scripts/session_stats.py` reports where past sessions spent tokens
  and time.
