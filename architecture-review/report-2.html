Problem
The session interface is shallow for review, compaction and revert: callers must manage the same ordering rules its implementation already manages for sends.
Solution
Move those operation lifetimes behind the existing session seam, starting with review and compaction.
Benefits
Locality puts queue and request races in one module; leverage lets mounted and hidden threads share the same behavior tests.
  • Interface is the test surface
  • Depth without another public module
  • Locality for pending request handling
Adapter scope: keep the existing command transport; tests already use a mock adapter. No new transport abstraction is justified by this review.
Deletion test: deleting ThreadSession would scatter stream and queue complexity into views. Keep this deep module; concentrate the remaining caller-owned implementation inside it. Current tests cover compaction queue blocking and stopping review after its request resolves. Add operation-level checks for delayed resolution, view changes and failure cleanup before replacing duplicated orchestration tests.
Evidence: ThreadSession explicitly says views toggle starting. Review manually seeds a turn because no turn/started event arrives. ThreadView.test.ts:1224 and threadSession.test.ts:359 cover parts of that contract separately. No ADR change required.
