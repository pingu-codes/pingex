# Contributing to Pingex

Thanks for helping improve Pingex. Make sure to follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Local workflow

Use Deno for the frontend and Tauri commands; do not introduce npm lockfiles. Before proposing a change, run the checks relevant to it:

```sh
deno task check
deno task lint
deno task test
deno task rust:test
```

Run `deno task rust:fmt -- --check` and `deno task rust:lint -- -D warnings` for Rust changes. Add regression coverage for changed behavior, especially at app-server and persisted-state boundaries.

## Changes

- Keep the Codex CLI and `codex://` protocol integration compatible unless a change is explicitly coordinated.
- Treat paths, credentials, tokens, and user thread content as private. Never add them to fixtures, screenshots, commits, or bug reports.
- Preserve the copy-only Pingu Codex migration path until a separately announced compatibility policy replaces it.
- Keep macOS-specific behavior documented rather than silently claiming cross-platform support.

Use a concise problem statement, implementation summary, and verification results when opening a pull request. Repository hosting and issue-tracker links will be provided by the maintainer when publishing Pingex.

## Testing

Always make sure changes are tested against. If changing the frontend make sure there's both unit and integration tests.

### Live end-to-end against a real Codex

`deno task test:e2e:codex` runs `src-tauri/tests/live_codex` against the installed `codex` binary and a real, cheap model (`gpt-5.6-luna` by default). It replays the exact request payloads the app sends (`src-tauri/src/codex/requests.rs`) and the composer's golden `turn/start` inputs (`tests/fixtures/protocol/turn-inputs.json`, generated by `src/lib/composer/turnInputFixtures.test.ts`) through skills, MCP, approvals, interrupts, resume, and the other app-server calls, so a payload the server rejects — or a method the installed Codex does not have yet — shows up before a user hits it.

It is opt-in (it spends tokens and needs a logged-in Codex home): it copies `auth.json` from `~/.codex-personal` or `~/.codex` (`PINGEX_E2E_AUTH_HOME` to override) into a scratch home and never touches your real config or sessions. `PINGEX_E2E_MODEL` and `PINGEX_E2E_CODEX` override the model and binary. Run it when touching anything under `src-tauri/src/codex/requests.rs`, `buildTurnInput`, or before a release; if you change what the composer sends, regenerate the fixture with `deno task test -u src/lib/composer/turnInputFixtures.test.ts` and rerun the live suite.
